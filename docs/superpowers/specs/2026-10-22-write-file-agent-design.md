# 给 LangGraph Agent 增加写文件/修改文件能力

- 日期：2026-10-22
- 状态：设计已确认（用户以“先就这样子做吧”授权）
- 工作区：`D:\Vibecoding\Langgraph`

## 目标

在现有 `graph_agent.py` 的 LangGraph 流程中新增 `write_file` 和 `edit_file` 两个工具，让模型根据用户的终端输入决定是否新建、覆盖或局部修改文本文件。

只处理文本文件；不删除文件、不追加内容、不创建目录、不执行命令。

## 已确认的决策

1. **写入范围**：不限制目录。用户指定哪个文件就写哪个，包括 `.env`、`graph_agent.py` 本身。
2. **操作方式**：`write_file` 负责新建/整文件覆盖；`edit_file` 负责精确的局部替换。
3. **防误覆盖**：修改已有文件前自动备份为 `.bak`；`.bak` 已存在时依次使用 `.bak.1`、`.bak.2`；备份失败则不写入。
4. **父目录**：不存在时直接报错，不自动创建目录。
5. **大小上限**：单次写入内容最多 5,000,000 字节；`edit_file` 只处理不超过 5,000,000 字节的文件。
6. **确认方式**：不做终端二次确认，依赖 `.bak` 恢复。
7. **文本边界**：新内容不能含 NUL；目标已有文件前 8KB 含 NUL 时拒绝修改/覆盖。

## 工具接口

```python
write_file(path: str, content: str) -> str
edit_file(path: str, old_text: str, new_text: str, replace_all: bool = False) -> str
```

工具描述（docstring）会明确告诉模型：

- 新建或整体重写用 `write_file`
- 局部修改必须先 `read_file`，原样复制 `old_text`，再调 `edit_file`
- 不要猜测文件内容
- 工具返回错误时如实转述，不要假装成功

## 路径处理

两个工具共用一个解析函数：

1. 去掉首尾空白和成对的单/双引号。
2. 展开 `~` 和环境变量。
3. 转为绝对路径，并用 `Path.resolve()` 解析符号链接。
4. 路径为空或无效时返回 `[错误] ...`。

写入使用解析后的真实路径，因此对符号链接的写入会落到链接目标上，备份也针对目标文件。

## `write_file`

### 流程

1. 解析路径，得到 `target`。
2. 父目录不存在或不是目录：返回 `[错误] 父目录不存在: ...`，不创建目录。
3. 目标是目录：返回 `[错误] 目标是目录: ...`。
4. `content` 编码为 UTF-8；编码后超过 5,000,000 字节：返回 `[错误] 内容过大 ...`。
5. 编码结果含 NUL：返回 `[错误] 内容包含 NUL，拒绝写入 ...`。
6. 目标已存在：
   - 目标不是普通文件：报错。
   - 前 8KB 含 NUL：返回 `[错误] 目标是二进制文件，拒绝覆盖 ...`。
   - 生成备份路径并 `shutil.copy2` 备份；失败则返回 `[错误] 备份失败 ...`，不写目标。
7. 用同目录临时文件写入，`flush` + `os.fsync`，再 `os.replace` 原子替换目标。
   - 目标原本存在时，尽量保留其权限位。
   - 任一步失败都删除临时文件，原文件保持不变。
8. 返回成功信息。

### 编码

- 新建文件和整体覆盖统一写 UTF-8，不带 BOM。
- 原文件的编码只保留在 `.bak` 中。

### 返回示例

```text
[新建] D:\...\demo.txt (128 字节, UTF-8)
[写入] D:\...\demo.txt (256 字节, UTF-8)
[备份] D:\...\demo.txt.bak
```

已有文件时，备份行另起一行返回。

## `edit_file`

### 流程

1. 解析路径，目标必须存在且是普通文件。
2. 文件大小超过 5,000,000 字节：返回 `[错误] 文件过大，暂不支持编辑 ...`。
3. 读取原始字节；前 8KB 含 NUL：返回 `[错误] 这是二进制文件，拒绝编辑 ...`。
4. 检测编码：
   - UTF-8 BOM：按 `utf-8-sig` 解码，记录需要写回 BOM。
   - 否则先试 UTF-8，再试 GB18030。
   - 都失败时返回 `[错误] 无法识别编码，拒绝编辑 ...`，避免用替换字符写回造成内容损坏。
5. `old_text` 为空：返回 `[错误] old_text 不能为空`。
6. 统计出现次数：
   - 0 次：返回 `[错误] 未找到 old_text ...`，提示先 `read_file` 并原样复制。
   - 多于 1 次且 `replace_all=False`：返回 `[错误] old_text 出现 N 次 ...`，要求更长的唯一片段。
7. `old_text == new_text`：返回 `[提示] 新旧文本相同，未修改`，不备份、不写盘。
8. 在内存执行替换：默认只替换第 1 处；`replace_all=True` 替换全部。
9. 按原编码和 BOM 编码回字节；编码失败则返回 `[错误] 新内容无法用原编码保存 ...`，不备份、不写盘。
10. 备份原文件（规则同 `write_file`）；失败则中止。
11. 原子写回，保留原权限位；原文件含 `\r\n` 时，解码/编码过程会原样保留，不做换行转换。
12. 返回替换处数、编码和备份路径。

### 返回示例

```text
[修改] D:\...\demo.txt (替换 1 处, 编码 utf-8)
[备份] D:\...\demo.txt.bak
```

## 备份规则

- 备份路径：`目标文件名 + ".bak"`。
- 若已存在，依次尝试 `.bak.1`、`.bak.2`，直到 `.bak.99`。
- 全部被占用：返回 `[错误] 无法生成备份文件名 ...`，不写入。
- 备份使用 `shutil.copy2`，保留时间戳和权限。
- 备份失败（磁盘满、无权限等）时，原文件不被修改。

## 原子写入

- 临时文件放在目标同目录，命名类似 `.<文件名>.tmp-<随机>`。
- 写入、`flush`、`os.fsync` 后关闭，再 `os.replace`。
- 失败时清理临时文件；不留下半截目标文件。
- 目标原本存在时，把原权限位应用到临时文件再替换。

## 错误处理

所有可预期错误返回 `[错误] ...` 字符串，不向 LangGraph 抛异常：

- 路径为空/无效
- 父目录不存在
- 目标是目录
- 文件不存在（`edit_file`）
- 无权限
- 二进制文件
- 无法识别编码（`edit_file`）
- 新内容无法用原编码保存（`edit_file`）
- 内容/文件超过 5MB
- 内容含 NUL
- `old_text` 为空
- 未找到 `old_text`
- 多处匹配但未指定 `replace_all`
- 备份失败
- 临时文件写入/替换失败

## 测试

新增 `test_write_file.py`，使用标准库 `unittest`：

### `write_file`

2. 覆盖已有文件并生成 `.bak`，`.bak` 内容为旧内容

### `edit_file`

10. 单处替换成功
11. 未找到 `old_text` 时报错，文件不变
12. 多处匹配且未 `replace_all` 时报错，文件不变
13. `replace_all=True` 替换全部
14. `old_text` 为空时报错
15. `new_text` 为空时删除片段
16. GB18030 文件编辑后仍为 GB18030
17. UTF-8 BOM 文件编辑后仍保留 BOM
18. `old_text == new_text` 时不写盘
19. 编辑后生成 `.bak`
20. GB18030 文件写入无法用 GB18030 表示的字符时报错，文件不变
